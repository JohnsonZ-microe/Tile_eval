# Y shared read port plus SRAM replay

Added YReadPortReplay for the registered COMMIT/DRAIN mux. It uses the old drain-bank register for current DRAIN routing, gives COMMIT priority on its bank, routes different-bank requests independently, updates even inactive address outputs, and exposes pre/post states so SRAM samples the previous registered request. Controller reset clears mux outputs/bank register but does not reset the SRAM.

Combined model replay over the existing yacc waveform passed 98,112 edges: 3,000 COMMIT requests, 3,024 DRAIN requests, 4,744 known data returns, and 1,280 unknown returns counted but not numerically compared. Every post-edge read enable, read address, drain-bank register and SRAM rvalid matches. SRAM input read addresses/enables are now generated by the mux model, not copied from observed SRAM ports. Request pulses/addresses from the FSM and write data remain observed inputs.

The waveform contains zero simultaneous same-bank or different-bank COMMIT/DRAIN request pulses. Those cases are therefore NOT waveform-calibrated. Unit tests sweep both old/new drain banks, both commit banks and all enable combinations (32 combinations), then compose registered mux and SRAM to check data latency and memory persistence across controller reset.

The waveform SHA-256 is bound in checks.json. Sources are fingerprinted in sources.json. Run check.py from this directory or by its full path with Python to reproduce. The actual Y FSM arithmetic, COMMIT/DRAIN producer addresses and write data are not yet generated independently; this is a component-integration step, not complete Y/Tile calibration, a physical macro check or a PPA conclusion.
